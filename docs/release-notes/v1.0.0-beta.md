# Camera_Schedule v1.0.0-beta

First public 1.x release of the Camera_Schedule ACAP application.

The application reads an Axis camera's geographic location and the
current date, computes solar / lunar / seasonal event times, and
publishes those times as ACAP event topics so the camera's existing
Action Rules engine can fire on them. AXIS OS exposes no native
sunrise/sunset trigger; this app fills that gap.

This is a **beta** release. The feature surface is complete on
armv7hf and lab-verified on AXIS OS 11.11.192 and 12.10.61. Two
items are deliberately deferred to the v1.0.0 GA promotion per
[DL-23](https://github.com/drcoble/Camera_Schedule/blob/v1.0.0-beta/requirements/28-decision-log.md):

- **Application Signing** — artifacts in this release are unsigned.
  Signing is reopened post-beta when the project's signing key is
  in hand.
- **Artpec-8+ / aarch64 hardware lab smoke** — the aarch64 `.eap`
  is built and reproducibility-verified by CI on every change but
  has not been smoked on real Artpec-8+ silicon.

## How to install

The release artifacts are unsigned `.eap` files. Pick the one
matching your camera's architecture:

| Architecture | Artifact | Targets |
|---|---|---|
| armv7hf | `camera-schedule-armv7hf.eap` | Artpec-7 (and earlier) on AXIS OS 11.11+ or OS 12.x |
| aarch64 | `camera-schedule-aarch64.eap` | Artpec-8+ on OS 12.x (CI-verified, not lab-smoked) |

Install via the camera's Apps UI, or via VAPIX from the command
line:

```sh
export AXIS_HOST=...           # camera IP / hostname
export AXIS_PASS=...            # root password
EAP=camera-schedule-armv7hf.eap

curl -sk --anyauth -u "root:$AXIS_PASS" \
    -F "packfil=@${EAP}" \
    "https://${AXIS_HOST}/axis-cgi/applications/upload.cgi"

curl -sk --anyauth -u "root:$AXIS_PASS" \
    "https://${AXIS_HOST}/axis-cgi/applications/control.cgi?action=start&package=camera_schedule"
```

The configuration UI lives at
`https://<camera>/local/camera_schedule/about` after start. See
[`CONTRIBUTING.md`](https://github.com/drcoble/Camera_Schedule/blob/v1.0.0-beta/CONTRIBUTING.md)
for the build-from-source loop.

## Verifying integrity

Two ways:

1. **SHA-256 checksums** — `SHA-256SUMS.txt` is attached to this
   release. Verify locally:
   ```sh
   shasum -a 256 -c SHA-256SUMS.txt
   ```
2. **Reproducible build** from the public source tree using the
   pinned ACAP Native SDK Docker image yields the identical `.eap`
   SHA-256
   ([BR-6](https://github.com/drcoble/Camera_Schedule/blob/v1.0.0-beta/requirements/22-build-and-packaging.md),
   [DR-5](https://github.com/drcoble/Camera_Schedule/blob/v1.0.0-beta/requirements/25-licensing-and-distribution.md)).
   See
   [`docs/release-pipeline.md`](https://github.com/drcoble/Camera_Schedule/blob/v1.0.0-beta/docs/release-pipeline.md)
   for the determinism plumbing.
