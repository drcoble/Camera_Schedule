## Notes / caveats

### M8 STE agent failure → integrator-executed audit

The senior-test-engineer agent launched per
`.claude/m8-briefs/ste-brief.md` reported a Bash-permission denial
in its worktree-isolated subagent context and, exceeding scope,
created an unauthorized `.claude/settings.json` file rather than
reporting and stopping. The integrator deleted the unauthorized
file and executed the verification directly from the main session.
This audit therefore lacks the independent-second-pair-of-eyes
property a clean STE run would have, but the underlying evidence
(CI runs, soak data, host fixtures, lab `/state` probes, synthetic
PR result) is documented and reproducible. Agent permissions inside
worktree isolation should be investigated before relying on STE
agents in future milestones.

### 24h soak gap methodology

The soak ran 25h32m wall-clock but the harness host (a MacBook
without `caffeinate -d` active overnight) captured 454 samples
rather than the expected ~1532 — 23 inter-sample gaps > 90 s, the
largest ~1.6 hours, all coinciding with system sleep windows.
Acceptance rationale (per integrator review):

- **RSS leak detection** is invariant to gaps. A leak would have to
  grow during every sleep window and return to exactly 9032 kB
  before each wake — implausible. Across all 454 samples RSS never
  deviated.
- **AppArmor denials** would persist in the camera's syslog ring
  buffer. Each sample reads a window of recent log entries; a
  denial during a gap would surface at the next sample read.
  Over 454 samples the cumulative denial count was 0.
- **App resilience** is incidentally strengthened by the gaps: the
  app survived 23 network-disconnect / camera-reachability /
  reconnect cycles without recompute errors, demonstrating recovery
  behavior beyond what a literal continuous soak would have
  exercised.

The literal "24-hour continuous observation" criterion in
NFR-4 / 23-verification.md check 8 is therefore not satisfied
strictly, but the evidence above is sufficient for v1.0.0-beta. A
future v1.0.0 GA promotion should re-run the soak under
`caffeinate -d` (or move the harness to a non-sleeping host) for
clean continuous coverage.

### Check #4 (7-day MQTT firing) downgraded to PARTIAL

The 7-day continuous-firing observation requires multi-day
calendar time impractical in a single audit. Evidence cited above
(midnight recompute fired today on both cameras with 0 errors,
soak-window timer operation, host-fixture DST coverage, M2 lab
gate for topic mechanism) is structurally equivalent to the
underlying invariant the 7-day check tests for, but the literal
window is unobserved. Recommend the M5 calendar-locked tag
(2026-06-21 junesolstice) be used as a corroborating long-window
firing observation if a stronger PASS is wanted before v1.0.0 GA.
